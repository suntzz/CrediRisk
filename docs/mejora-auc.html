¿Y por qué no 0,78?

El CSV es la base pública Home Credit Default Risk recortada (el id 100002 coincide fila a fila: ingreso 202.500, monto 406.597,5, cuota 24.700,5, incumplió). Con estas 23 columnas el techo observado es ~0,76–0,77; llegar a 0,78 exige traer columnas de fuera, y la regla de la competencia no lo permite.

Cómo se midió
  • Validación cruzada de 5 pliegues × 3 repeticiones sobre entrenamiento + validación (42.202 filas). El AUC «de clientes que el modelo no vio» sale de ahí.
  • El preprocesador se ajusta dentro de cada pliegue, así nada del pliegue de prueba se filtra.
  • Intervalos por bootstrap pareado: mismos clientes para el modelo de antes y el nuevo.
  • Las redes nuevas se midieron con una sola repetición (5 pliegues) por tiempo; por eso las mezclas con redes usan la repetición 0 de todos los modelos.
  • Modelo final = 0,85 × (0,90 árbol + 0,10 redes, con score) + 0,15 × (0,90 árbol + 0,10 redes, sin score). Árbol: HistGradientBoosting sobre variables crudas + razones, 5 semillas. Redes: las 3 de siempre, con el preprocesador corregido.
  • Las redes quedan con peso 0,10: con los pesos buscados de 0,05 en 0,05 no suman ni restan de forma significativa frente al árbol solo; se conservan porque la arquitectura es híbrida.
  • Peso del modelo con score: entre los pesos cuyo AUC no es significativamente menor que el mejor, el de menor dependencia del score. Revolving loans no mejora con un peso propio.
  • En la prueba vieja, producción se entrenó solo con entrenamiento; el nuevo con entrenamiento + validación.
  • La prueba vieja (7.448 filas) ya la había usado el equipo antes; se miró una sola vez, al final. El número confiable es el de validación cruzada.
